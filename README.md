# game-server-setups

Automates setup of my game servers running in Docker.

## Quick start

```bash
python main.py
```

The CLI will ask which game servers you want to set up, then:

1. Generates a `docker-compose.yml` in the game's folder.
2. Generates/updates a single `.env` at the repo root (gitignored) with your
   tokens/passwords. Every game's compose loads it via `env_file: ../.env`.
   See `example.env` for the full template.
3. Creates the on-host groups, users and directory structure needed on first run.

After the script finishes:

```bash
cd plutonium_t6_zombies
docker compose up -d
```

## Plutonium T6 Zombies — first-time setup

1. Run `python main.py`, say yes to **Plutonium T6 Zombies**.
2. Get a server key at <https://plutonium.pw> (or say yes to LAN mode to skip).
3. The script creates `/mnt/ssd/config/aio-plutonium-t6/` (configurable).
4. **Copy your merged BO2 game files + DLCs** into:
   ```
   /mnt/ssd/config/aio-plutonium-t6/server/pluto_t6_full_game/
   ```
   This folder is mounted read-only into the container at `/t6server/game_files`.
5. `cd plutonium_t6_zombies && docker compose up -d`
6. On a fresh host, log in to GHCR first to pull the **private** image — see
   [`docs/docker-registry-login.md`](docs/docker-registry-login.md).
7. First boot will take a few minutes while it copies game files, downloads
   server configs, runs the Plutonium updater, downloads IW4M-Admin, and
   configures Wine.

### Changing maps (live, from inside the game)

No scripts or SSH needed — open the in-game console with `~` and use RCON.
See **[`docs/plutonium-t6-rcon.md`](docs/plutonium-t6-rcon.md)** for RCON
login and the full map-reference table.

## Adding a new game server

Three files to touch:

1. **`main.py`** — add a line to the `GAMES` dict and write a `configure_<name>_env(env)` function + matching `ENV_CONFIG` entry.
2. **`container_configs.py`** — add a `<name>()` method returning the full `docker-compose.yml` content string.
3. **`server_setup.py`** — add a `<name>()` method that creates the group/user and directory structure.

Each game gets its own folder with a static `docker-compose.yml` that was
generated by the CLI. The script re-generates it cleanly on re-runs.

## Repo structure

```
main.py                      # CLI entry point (writes .env at repo root)
container_configs.py          # docker-compose.yml generators per game
server_setup.py               # group / user / folder creation per game
.env                         # shared settings for ALL games (gitignored, not in repo)
example.env                  # template for .env - copy it or run main.py
helper/
  __init__.py
  EnvManager.py               # env file reader/writer (shared with ezarr)
docs/
  plutonium-t6-rcon.md        # RCON login + map changes via the in-game console (~)
  docker-registry-login.md    # one-time GHCR login to pull the private image
plutonium_t6_zombies/
  docker-compose.yml          # generated — do not edit manually
  server-launch.sh            # reference copy of the fork's patched launch script (baked into the image)
  CHANGES.md                  # changelog of fixes vs upstream image
satisfactory_server/
  docker-compose.yml          # generated — do not edit manually
```
